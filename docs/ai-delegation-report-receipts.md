# AI 위임 결과의 전달·수신 확인

하위 실행 완료와 상위 AI의 후속 응답 종료는 서로 다른 사건이다. 상위 AI가 결과를 받은 뒤 긴 턴에서 다음 작업을 조정하더라도 이전 하위 위임을 활성 상태로 남겨 후속 위임을 막지 않는다.

## 상태와 안전 조건

- `waiting-parent`: 미전달 결과. 상위 대화가 유휴 상태이면 기존 자동 보고로 전달한다. 상위 AI가 실행 중이면 별도 턴을 만들지 않는다.
- `waking-parent`: 결과 전달 요청 접수. `starting`이나 자원 대기만으로 수신 완료를 판단하지 않는다.
- `completed` + `reportStatus=received`: 하위 실행·필수 통합이 끝났고, 기존 요청의 대상 대화·실행 턴·전달 원문 해시로 전달을 확인했거나 담당 상위 AI가 정확한 결과 해시를 명시해 수신 확인했다.
- `parent-wake-failed`: 전달 확인 실패. 하위 실행 성공 여부와 분리해 표시하며, 조회나 재전달이 하위 작업을 다시 실행하지 않는다.

`completed`는 요구사항 검수나 프로젝트 전체 완료, 새 작업의 사용자 승인을 뜻하지 않는다. 상위 AI의 현재 실행 상태는 대화 런타임 표시에서 확인한다. 후속 위임에는 기존 승인 범위·카드 관계·대상 대화 런타임·작업공간 검사를 그대로 적용한다.

## 실행 중인 상위 AI의 결과 회수

1. `mindnprogress_list_ai_delegations`를 대상 카드 필터와 `includeResult=true`로 호출해 저장된 결과 원문, `resultHash`, `resultTurnId`, `updatedAt`을 확인한다. GET은 위임 상태를 변경하지 않는다.
2. 원문을 실제로 읽은 담당 상위 AI가 `mindnprogress_refresh_ai_delegation`에 `expectedUpdatedAt`과 `acknowledgeResultHash=resultHash`를 전달한다. 생략하면 기존 상태 조회 기능이다.
3. 서버는 불변 시작 대화·상위 카드, 현재 연결, 하위 실행·통합 완료, 결과 해시·턴을 검증한다. 다른 대화, 오래된 상태, 미캡처·변조 결과, 미완료 통합은 거절한다.
4. 수신 확인은 위임 메타데이터만 종결한다. 카드·문서 버전·코드·작업공간·승인을 바꾸거나 AI를 실행하지 않는다. 해당 대화의 후속 위임을 막던 활성 위임 기록은 해제되지만, 실제 실행 중인 대화를 중복 실행할 수는 없다.

MCP 도구 수는 늘리지 않는다. 기본 목록에는 긴 원문을 포함하지 않으며, 전체 대화의 최신 응답으로 과거 위임 결과를 대체하지 않는다.

## 재시작 및 기존 기록

재시작 전 `running` 또는 실행 후 중지 상태로 관측한 동일 보고 요청의 대화·턴·전문 해시와 결과가 남아 있으면, 그 근거로 보고 수신을 복원한다. 이미 전달된 결과는 상위 대화가 중지되거나 요청 기록이 만료되어도 다시 보내지 않는다. `reportReceipt`에 수신 방식·시각·대화·턴·해시를 보존한다.

미전달 결과는 상위 대화가 유휴 상태일 때 자동으로 전달하므로 재시작 후 상위 AI가 다시 실행될 수 있다. 전달 근거가 없거나 실패한 기록까지 일괄 완료 처리하지 않는다. 그런 기록은 결과를 읽은 담당 상위 AI의 명시적 수신 확인 또는 기존 결과 전달 재시도 절차를 사용한다.
