# AI 대화의 사용자 권한 경계

## 메인 머신 허용

`server/data/_users.json`의 계정별 `mainMachineAllowed` boolean으로 관리한다. 저장 경로를 변경한 환경에서는 해당 데이터 디렉터리의 `_users.json`을 사용한다. 처음 필드가 추가될 때 `user-editor`만 `true`, 나머지 기존 편집자는 `false`로 저장한다. 새 편집자는 항상 `false`다. 명시적으로 저장한 `false`는 재시작해도 유지된다. 활성 관리자는 역할로 허용한다.

관리자 로그인 세션으로 `GET /api/admin/editors`에서 현재 값을 조회하고, `PATCH /api/admin/editors/:id`에 `{"mainMachineAllowed":true}` 또는 `{"mainMachineAllowed":false}`를 보낸다. 일반 편집자·통합 Bearer로는 관리자 API를 사용할 수 없다. 이번 변경은 관리자 API를 제공하며 화면에 별도 입력 항목은 추가하지 않는다.

허용되지 않은 계정은 메인 머신의 새 대화·위임·그룹 지시를 시작할 수 없다. 본인 소유 서브 머신은 분산 작업 설정을 켜서 사용한다. 관리자가 허용을 해제하면 이후 요청과 아직 전달되지 않은 대기 지시에 반영한다. 이미 실행 중인 Aion 대화는 종료하지 않는다.

## 대화 접근과 귀속

- 대화의 origin·영속 귀속·임시 귀속·연결 기록에 있는 시작자를 대조한다. 서로 다른 시작자 기록이 충돌하면 접근을 거부한다.
- 전문 조회, WebUI 주소 발급, 담당 지정, ID 조회·연결, 위임·그룹 지시 재개는 시작자 본인과 실행 머신 권한을 모두 요구한다. 관리자도 타인의 소유권을 얻지 않는다.
- 시작자가 없는 이전 대화는 메인 머신이 허용된 계정만 접근한다. 서브 머신의 소유권 검사도 유지한다.
- 연동 요청의 `x-mnp-ai-editor-id`, 귀속 토큰, 현재 대화 기록이 서로 다른 편집자를 가리키면 403으로 거부한다. Runner 요청은 토큰의 시작자가 머신 소유자와 같은지도 확인한다.
- 전문 응답의 `attributionToken`과 `x-mnp-ai-attribution` 값을 `[비공개]`로 가린다. 내부 대화 원문은 수정하지 않는다.
- 세션 메시지는 인증 헤더의 현재 대화와 본문의 발신 ID가 같아야 한다. 발신·수신 시작자를 각각 하나로 확인할 수 있고 같은 계정일 때만 기록된 머신으로 중계한다. 시작자 미상 대화의 메시지는 거부한다.

## 적용

사용자 승인 후 기능 브랜치를 main에 병합하고 MnP 서버를 재시작한다. 첫 시작 시 기존 사용자 파일에 허용 필드를 저장하므로 적용 전 일반 데이터 백업 절차로 `_users.json`을 보존한다. 기존 대화의 시작자를 임의로 채우거나 소유자를 옮기는 마이그레이션은 하지 않는다. 동료 계정은 관리자가 명시적으로 허용하기 전까지 메인 머신을 사용할 수 없다.

문서별 권한, 서버 설정 권한, Dooray 사용자별 키, HTTPS는 이 계약의 범위 밖이다. 서버 OS·공용 통합 토큰 보유자는 신뢰 영역에 남는다. 공용 토큰만으로 각 로컬 Aion 대화를 암호학적으로 식별하는 구조는 아니므로, 서버 파일에 직접 접근하는 악성 사용자를 격리하는 기능으로 해석하지 않는다.
