## 기존 부분 수정 업무와 현재 구현의 차이

별도 카드 `node-mv30wgu0-9065d1`은 planned/0%이며 공유 지식은 비어 있다. 설명의 “MCP·웹이 전체 PUT에 의존”은 현재 코드와 다르다. `docs/map-content-patch.md`, `mcp/server.mjs:538`, `src/App.tsx:4344,4373,6001`에서 일반 편집은 이미 PATCH다. 추가 생성할 API가 아니다.

현재 전환은 요청 크기를 줄였으나 전체 응답, 전체 문서 버전 충돌, 영속 일반 요청 ID는 그대로다. 웹의 409 병합은 겹치는 항목에 내 변경을 유지하고 최신 기준 patch를 다시 보낸다(`App:4365–4386`). 이는 변경 대상 사전조건을 보존하는 최종 충돌 계약과 구분해야 한다. `tests/map-content-patch-api.test.mjs:24,137`은 2MB 초과 문서와 두 동시 요청의 200/409를 검사하지만, 5MB·10MB·전 경로·재시작까지 완료한 증거가 아니다. 이번에는 기존 테스트를 실행하지 않았다.

공통 저장·충돌·중복 요청 엔진은 02·03·04가 주 소유한다. 기존 별도 카드는 남은 웹 전송/동기화/실행 취소/충돌 병합 소비자 전환과 2MB·5MB·10MB 전체 완료 판정을 계속 소유한다. 06은 조회·응답 구성·반복 호출만 소유한다. 별도 카드 상태나 요구사항을 이 감사에서 변경하지 않는다.
