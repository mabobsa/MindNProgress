# REQ-MNP-05 잠금 범위·대기열·재시도 제한

담당 카드: `node-mvq4frj2-2029e5`. 기준 커밋: `62506a6ef2c1075e7329704dedf5101bd0a38bec`.
구현 커밋: `28193f6bc3482d9ee71468300c377bac341b14b5`, 원격 오류 경계 보완: `2bc4743b1a128dc2cd4f86731735dfda4843019f`.
확정 기준은 [공통 계약 1·4·5·6·8절](contract-v1.md)과 담당 카드의 원래 완료 조건이다. 02의 잠금 순서, 03의 원문·읽기 조건, 04의 영속 결과·후속 효과 격리를 재사용했다. 구현자 자체 검증 완료이며 상위 인수·07 독립 통합 검수와 구분한다.

## 기한과 취소

`storageBudget.mjs`의 요청 문맥을 HTTP 진입부터 본문 수신, 자원 탐색·재수집, 잠금, 저장 준비까지 전달한다. 일반 전체 기한은 30초, 명시적인 다중 문서 이동·재구성은 60초다. 누적 자원 대기는 일반 5초, 다중 자원·수명주기 10초이며 모든 키·재수집·같은 ID 재시도에 누적한다. 대기열은 키당 128개, 프로세스의 모든 공통 큐를 합쳐 1,024개다. FIFO 읽기·쓰기 잠금과 기존 자원 정렬·중첩 재사용·역순 해제를 유지한다.

본문은 잠금 전에 수신·파싱하며 기존 2,000,000바이트 제한을 유지한다. 본문·대기 단계의 취소와 연결 종료는 리스너·타이머·대기자·앞서 획득한 키를 정리한다. 타이머 실행이 늦어져도 잠금을 넘길 때 기한을 다시 확인한다. `WRITE_QUEUE_FULL`과 `LOCK_WAIT_TIMEOUT`은 503, `outcome: not-applied`, `retryAfterMs: 250`이며 terminal journal 결과를 만들지 않는다. 전체 기한 종료는 `REQUEST_DEADLINE_EXCEEDED`다.

`storageChanges.run`의 영속 준비 직전에 최종 취소·기한을 확인한다. 준비가 시작되면 연결 종료로 rollback하지 않고 04의 확정·복구를 마친다. 응답 예산이 끝나고 연결이 남아 있으면 같은 ID의 202를 반환한다. commit marker 이후 복구, 부모 문서 조회 허용과 후속 효과만 격리하는 경계, 기존 rename 6회/465ms 상한은 유지한다.

서버는 같은 논리 ID의 전체 기한·누적 자원 대기를 메모리에 유지한다. MCP는 최초 기한을 `_mcp-write-intents`의 준비 기록에도 보존하고 `X-MNP-Deadline-At`으로 전달한다. 서버 재시작을 사이에 둔 MCP 재전송도 최초 기한을 유지한다. 직접 HTTP 재시도도 같은 절대 기한 헤더를 전달해야 한다. 결과 전용 조회와 이미 기록된 결과의 반환에는 별도 응답 예산을 허용하므로 실행 기한이 끝나도 기존 결과를 확인할 수 있다. ID 없는 레거시 요청은 호출 간 중복 방지·논리 기한 공유를 보장하지 않는다.

## 외부 대기와 로컬 확정

- `conversation-display`와 머신 전송·작업공간 경로에서 콘텐츠 RMW용 바깥 잠금을 제거했다. 실제 문서 변경은 기존 소유 모듈의 보호 구간에서 수행한다.
- launch callback은 catalog·문서·AI 상태 자원을 순서대로 획득해 예약 토큰, 시작 정보, 문서 버전, 수명주기, 귀속을 기록한다. 잠금을 놓고 AionUi 대화·작성자 정보를 확인한 뒤 같은 자원을 다시 획득해 토큰·권한·버전·현재 상태를 대조하고 연결한다. 같은 예약을 탈취할 수 없다. 기존 통합 계정의 정당한 시작 요청을 보존하며 일반 편집자의 활성·편집 권한도 다시 확인한다.
- 완료 이력 정리는 보호 구간에서 원문과 리스 후보를 복제하고 백업·결과 파일 읽기를 밖에서 수행한다. 다시 보호한 상태의 fingerprint가 다르면 삭제를 보류한다. 리스 정리에는 원래 허용 ID·기대 원문 검사를 계속 전달한다.
- `RemoteWorkspacePool`은 상태 큐를 유지하면서 Runner 호출, Git 준비·staging·통합·산출물 정리 대기를 밖에서 수행한다. 리스별 예약 토큰·원문·소유권·풀 승인과 registry를 재검증한다. 실제 통합은 기존 로컬 통합 잠금으로 직렬화한다. 결과가 불명확한 원격 명령은 영속 `pendingOperation`에 같은 작업 ID로 남겨 다른 명령을 막는다. 재획득 실패 시 메모리 예약은 정리하고 영속 작업을 재확인한다. 실행 전 거부가 확정된 runtime·dirty·허용 경로 오류만 재접수를 허용한다.
- 산출물 대기도 같은 유한 큐를 사용하고, 접수된 읽기·쓰기를 모두 마친 뒤 완료 파일을 정리한다. 대기에서 깨어난 산출물 요청은 완료·봉인·머신 귀속을 다시 확인한다.

원격 풀·산출물·보고 라우트도 실행 전 큐 거부는 공통 503 계약을 전달한다. 외부 작업 뒤 재검증 큐 진입에 실패한 경우에는 `REMOTE_WORKSPACE_REVALIDATION_PENDING`, `outcome: processing`으로 구분한다. 이때 변경 없음으로 단정하거나 새 명령을 실행하지 않고 보존된 같은 명령의 결과를 확인한다.

정상 Runner long-poll 기본 25초와 모델·사용자 대기는 저장 잠금 대기가 아니다. long-poll을 `runner-long-poll` 및 `runnerLongPollMs`로 구분하고 백그라운드 모델 작업은 요청의 저장 예산에서 분리한다. 종료 신호는 기존 `RUNTIME_STOPPING` 503 처리로 전달한다.

## 유한 재시도와 진단

MCP 자동 재시도는 안전한 admission 오류와 응답 유실에 한정해 최초 포함 최대 3회다. 지연은 100/200ms와 ±25% jitter이며 서버 `retryAfterMs`가 더 크면 그 이상 기다린다. 재시도는 최초 HTTP 본문·읽기 조건·권한 scope·같은 ID·전체 기한을 유지한다. handler를 다시 실행하거나 최신 기대값을 계산하지 않는다. 인증·형식·필드·의존 충돌은 자동 재시도하지 않는다. 같은 ID의 동시 합류는 실행 큐를 중복 점유하지 않는다.

기존 느린 요청 기록과 `mindnprogress.storage.diagnostic` 채널에 요청 ID, 자원, 대기 단계, `queueWaitMs`, `lockHoldMs`, `persistMs`, `externalWaitMs`, 재시도 수, 결과를 연결했다. launch URL의 token은 가리고 유효한 저장 ID만 진단에 넣는다. 요청 본문·인증 비밀을 새 진단에 넣지 않으며 전 요청 상세 계측을 상시 켜지 않는다.

최초 영향 회귀는 141개 중 139개 통과였다. 통합 계정 callback 거부를 수정하고 재검증했으며, 96개 문서의 병렬 fixture 시작 시간 초과는 원래 제한 그대로 단독 재실행해 통과했다. 원격 경로 거부의 예약 잔류와 종료 500도 수정 후 통과했다. 날짜 fixture는 오늘 서울 날짜의 백업을 선택하도록 고쳤다. 기존 산출물 시험은 큐 구현에 맞춰 접수 정지 지점만 바꾸고 원래 오류·파일 판정은 보존했다. MCP 응답 유실 시험은 자동 재시도 3회를 모두 소진하도록 장애 횟수를 바꾸고 원래 재접속·최초 의도 판정을 유지했다. 판정 기준·기대 내용을 완화하지 않았다.

정적 검사와 `tsc -b && vite build`가 통과했다. 기존의 무관한 `no-unsafe-finally` 경고 1개와 번들 크기 경고는 남았다. 전체 07 부하·실제 화면 인수, 06 조회 개선, 운영 배포·장애 주입·실제 Runner/AionUi 실행은 이번 범위에 포함하지 않았다.

## 변경 분리와 완료 범위

기준 archive에 담당 변경만 넣은 `.tmp/req-mnp05-final/isolated`에서 검증했다. `node_modules`만 기존 설치에 연결하고 운영 데이터는 복사하지 않았다. `server/index.mjs`의 착수 전 다른 업무 109줄을 원문 단위로 제외해 커밋했으며, 검증 후보와 실제 커밋의 19개 파일이 Git 정규화 후 일치한다. 다른 추적 수정 5개·미추적 파일 8개는 시작 SHA-256과 일치하고 기존 `.tmp`를 보존했다.

이번 범위의 필수 미완료는 없고 선택 개선도 없다. 담당 카드의 공유 지식에는 후속 소비 계약만, 수행·검증과 커밋은 결과 댓글에 기록한다. 상위 인수·07 독립 검수는 별도 단계이며 이 카드의 새 종료 조건으로 추가하지 않는다.
