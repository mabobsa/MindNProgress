# 현재 문서의 AI 배치 제안

문서 목록 우클릭 → **AI 배치 제안**에서 사용한다. 문서 재구성·분할과 달리 현재 문서의 카드 위치만 정리한다. 편집자 전용이며 요청을 시작한 계정만 조회·제출·취소·적용할 수 있다.

휴대폰에서는 왼쪽 위 폴더 버튼 → 문서 이름을 약 0.5초 길게 누르기 → **AI 배치 제안**으로 들어간다. 그룹 이름도 길게 누르면 그룹 메뉴가 열린다. 길게 누르기 전에 손가락을 움직이면 목록 스크롤로 처리하며, 메뉴를 연 뒤 손을 떼어도 문서 선택이나 그룹 접기가 실행되지 않는다.

캔버스의 카드는 약 0.5초 길게 누르면 메뉴가 열린다. 누른 채 끌면 메뉴를 닫고 카드와 하위 카드를 이동한다. 손을 뗀 뒤에도 메뉴가 열린 같은 카드를 다시 끌면 다시 기다리지 않고 이동한다. 메뉴 버튼을 누르면 해당 명령을 실행하며, 일반 카드 쓸기는 기존처럼 화면 이동이다. 터치 취소·두 손가락 화면 조작 전환 시 진행 중 카드 이동을 되돌리고, 확정한 이동은 실행 취소 한 번으로 복원한다.

## 사용자 흐름

1. 목표 캔버스 비율 **4:3 / 16:9 / 21:9**를 선택하고 새 요청을 만든다. 기본은 **16:9**이며 해상도를 선택하거나 크기를 제한하지 않는다. 휴대폰에서 요청해도 이 목표는 바뀌지 않는다. 저장된 원본과 Ref의 현재 표시 내용을 고정하고 모든 카드·이미지의 실제 크기와 돌출 영역을 측정한다. 저장되지 않은 편집이 있으면 요청하지 않는다.
2. 기존 AI 선택 화면에서 대화를 시작한다. AI는 요청의 승인 범위·스냅샷·실측값을 조회하고 모든 카드 ID의 순서와 제안 이유를 제출한다. 좌표·크기를 직접 제안하지 않는다.
3. 제안을 수신한 화면에서 미리보기를 열면 실제 카드 렌더러로 재측정 → 재배치 → 최종 검증한다. 기본 **화면 균형형**, 형태가 다른 **가로/묶음 분산형**, 기존 **계층형 · 비교용** 중 현재 구조에서 구별되는 후보를 비교하고 이유를 확인한다. 동일한 후보는 중복 표시하지 않는다.
4. 선택 비율의 미리보기에서 **현재 실제 확대율**과 전체 카드 수를 확인한다. 확대율은 창 크기와 확대·축소 조작에 따라 바뀌지만 배치 좌표와 카드 크기는 바뀌지 않는다. 작은 글씨는 확대해서 읽으며 목표에 맞추기 위해 카드·내용·실제 크기를 변경하지 않는다.
5. 제안 화면에서 확인 체크 후 적용하면 검증한 좌표만 저장한다. 후보·목표·현재/제안 비교 전환은 확인 체크를 해제한다. 후보나 목표를 바꾸면 새 토큰으로 재측정·검증하고 마지막 확인한 배치만 적용한다. 취소·제안·미리보기는 원본을 수정하지 않는다. 닫기는 요청을 보존한다.

MnP 문서 관리 팝업의 테마·글자 계층·버튼을 재사용하되 실제 카드에는 관리 화면의 축소 스타일을 적용하지 않는다. 밝은/어두운 테마, 좁은 화면 자동 맞춤, 키보드 포커스 순환 및 ESC 닫기를 지원한다. AI 선택 화면이 열렸거나 저장 중이면 부모 팝업의 ESC를 막는다.

## 배치 계약

- `src/utils/cardLayout.mjs`의 `card-layout-v3`는 카드 1~2000개를 지원한다. 역할·표시 유형으로 분류해 같은 부모 안에서 같은 종류를 묶고, 하위 트리와 복수 독립 계층을 보존한다.
- 깊이별 고정 열 대신 가지 전체의 점유 사각형을 여러 행·열로 묶는다. 비율 `r`의 단위 면적 프레임에 대한 비용 `max(배치 너비/√r, 배치 높이×√r)`과 비율 차이를 비교하므로 절대 해상도는 계산에 사용하지 않는다. 같은 문서·실측 크기·AI 순서·비율이면 FHD·QHD·그 외 크기에서도 후보와 좌표가 완전히 같다. 대표 루트와 모든 부모→자식의 오른쪽 확장을 유지한다.
- 미리보기 프레임은 선택한 비율을 따르며 실제 렌더러가 전체 구조를 화면에 맞춘다. 현재 카메라 확대율이 65% 미만이면 확대 안내를 표시한다. 예상 해상도 배율은 계산하지 않는다. 카드·계층 보존이 우선이므로 배치 외곽의 정확한 목표 비율 일치나 많은 카드·깊은 계층의 한 화면 가독성을 보장하지는 않는다.
- 점유 영역 사이 최소 32px, 오른쪽 계층 확장, 하위 트리 비혼합을 우선한다. 대표 루트의 원래 위치를 기준점으로 사용한다.
- 독립 자료는 실제 지식 연결과 공통 상위 영역을 기준으로 후보 위치를 평가한다. 주요 지식의 길이·교차 비용을 더 크게 반영한다. 연결 없는 카드는 별도 외곽 영역에 종류별로 배치한다. 전역 최적 교차 최소화를 보장하는 알고리즘은 아니다.
- 카드 ID·노드 순서·데이터·이미지 및 Dooray 표시 크기·모든 연결선은 그대로 보존한다. 위치 외 노드 필드를 재구성하지 않는다.
- `ReconstructionMap`의 `layoutProposal` 모드에서 실제 카드·이미지·Ref·Dooray 및 지식선을 렌더링한다. 폰트와 이미지 로딩을 기다리고 배지·접기 버튼을 포함해 측정한다.
- 측정 누락·이미지 로딩 실패·잘못된 계층은 적용을 차단한다. 원본/Ref 표시 내용 변경은 새 요청, 미리보기 표시 크기 변경은 재측정·재검토가 필요하다. 서브픽셀 반올림 오차는 1px 범위에서 허용한다.
- 기존 문서 재구성의 `layoutMindMap` 계약은 그대로 유지한다.

## API와 MCP

요청은 `_card-layout-requests.json`에 저장한다. 미리보기 토큰은 메모리에만 보관하며 30분 만료·최대 20개이다. 서버 재시작 후 기존 AI 제안은 다시 열 수 있지만 재측정·검증 없이 적용할 수 없다.

| 경로 | 역할 |
| --- | --- |
| `GET /api/card-layouts?mapId=...`, `GET /api/card-layouts/:id` | 소유 요청 목록과 최신 상태 |
| `POST /api/card-layouts` | `proposalOnly:true`인 분석·제안 요청, 선택적 `target:{ratio:"4:3"\|"16:9"\|"21:9"}` |
| `POST /api/card-layouts/:id/capture` | AI 요청 전 실제 크기 저장 |
| `POST /api/card-layouts/:id/proposal` | `baseRevision`, `plan:{order,reason}` 제출 |
| `POST /api/card-layouts/:id/preview` | 선택적 `target`, `variant:balanced\|spread\|hierarchy`; 후보 목록·크기·배치 비율과 선택한 배치 반환 |
| `POST /api/card-layouts/:id/measure`, `/verify` | 선택한 목표·후보에 결속된 토큰으로 실측·검증 |
| `POST /api/card-layouts/:id/apply` | 승인·소유자·버전·표시·최종 측정 확인 후 위치 저장 |
| `POST /api/card-layouts/:id/cancel` | 원본을 바꾸지 않고 요청 종료 |

MCP에는 `mindnprogress_get_card_layout_request`, `mindnprogress_submit_card_layout_proposal`만 노출한다. 적용·측정 도구는 노출하지 않는다. 배치 AI 대화는 `purpose:card-layout`으로 요청에만 연결하며 원본 카드의 대화 목록이나 버전을 변경하지 않는다. 기존 시작 전문의 `get_context`로 편집자·AI 귀속을 먼저 바인딩한다.

기존 v1 요청에 목표 필드가 없으면 16:9로, v2의 `target:{width,height}` 요청은 해당 비율로 정규화한다. 픽셀 크기는 유한한 양수이며 지원 비율과 일치하면 제한 없이 호환한다. 조회만으로 저장 파일을 다시 쓰지는 않는다. 새 요청과 응답의 목표는 `{ratio}`만 사용한다. AI의 `plan:{order,reason}` 계약은 유지한다. 적용한 요청에는 `appliedLayout:{version,target,variant}`를 남긴다. 최신 UI는 이전 버전의 미리보기 적용을 막으므로 서버와 UI를 함께 갱신한다.

저장 시 문서 변경 게이트와 버전 비교로 동시 편집을 차단하고, 정규화된 최종 payload의 노드·연결선을 원본과 비교하여 위치 외 변경을 거부한다. 적용 이력은 기존 문서 revision 백업에 남는다. 실제 AI 실행에는 갱신된 API 서버와 새 MCP 도구를 로드한 세션이 필요하다.

## 검증

`node --test tests/card-layout.test.mjs tests/card-layout-requests.test.mjs tests/card-layout-api.test.mjs`

- 역할 혼합·이미지·독립/공유 자료·복수 트리·32px 여백·루트 고정·누락 없음·순환/다중 부모 거부
- 1500개 깊은/넓은 계층 및 독립 카드
- 21개 카드의 비율 적합도 개선·후보 중복 제거·복수 트리 및 독립 카드 가로 배치·세 비율로 분산한 30개 결정적 혼합 사례의 하위 트리 영역 보존
- 세 목표 비율·기본 16:9·FHD/QHD/임의 크기의 전체 후보 일치·후보 및 비율 전환 시 이전 토큰 무효화·v1/v2 요청 호환·마지막 선택한 후보/목표 저장
- 소유자·승인·제안 revision·원본/Ref 변경·표시 크기 변경·만료·재시작·취소·위치 외 데이터 보존
- 격리 API 서버와 실제 MCP 클라이언트의 제출 및 Aion 대화 귀속 연결

PowerShell에서 `$env:MNP_LAYOUT_BROWSER='1'`로 위 API 테스트를 실행하면 별도 headless Edge 프로필로 실제 UI도 검증한다. 먼저 `npm run build`를 실행한다. 테스트 데이터에는 Ref·Dooray·이미지·복수 트리·공유 지식·연결 없는 카드를 포함한다. 후보/비율 전환의 확인 초기화와 재검증, 세 비율의 FHD·QHD·모바일 화면과 좌표 보존, 표시 확대율과 실제 카메라 확대율 일치, 확대 조작 시 좌표 불변, 마지막 선택 좌표 저장을 확인한다. 실제 사용자 데이터나 외부 AI 모델은 사용하지 않고 Aion 응답만 모의한다. 밝은/어두운/모바일 화면 PNG는 테스트 출력의 임시 산출물 경로에 남긴다.

동일 테스트에 `$env:MNP_TOUCH_MENU_BROWSER='1'`을 함께 지정하면 터치 메뉴·이동 검증만 실행한다. `tests/helpers/touchMenuBrowser.mjs`는 실제 CDP 터치 입력으로 문서/그룹 길게 누르기, 메뉴 버튼 실행, 스크롤과 구분, 카드 드래그·재터치·하위 동반 이동·저장·실행 취소·터치 취소·두 손가락 전환을 검증한다. 실기기의 OS별 브라우저 검증과는 구분한다.
