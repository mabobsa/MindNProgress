## 추가 평가: BEH-02 반복 실행 (Claude)

### 판정 기준

- (다) 승인 근거를 어떻게 전달할지 언급하지 않았다 → 부분

- 1차의 개정 전 통과·개정 후 부분 차이는 같은 버전 안의 실행 편차 범위에 있다. 반복 실행에서 개정 후가 개정 전보다 나빠진 경향은 없다.
- 10회 모두 같은 승인 지침을 읽었다(이벤트 안 `approvalEvidence` 등장 11~34회). 이번 개정은 승인 관련 지침 문구를 바꾸지 않았다.
- 2026-10-29 평가(Claude 4회 모두 명시)와 비교하면 이 항목은 원래 실행마다 흔들리는 항목으로 보인다. 다만 데이터는 같아도 개정 전 코드(`65704ea` → `131eace`)와 Claude Code 버전(2.1.312 → 2.1.314)이 달라 직접 비교하지 않는다.

## 관찰과 한계

- 네 실행 모두 예외(`contextOverride`)를 쓰지 않았다. 대화에만 있던 맥락을 지시로 옮길 수 있다고 판단해 기본값인 새 대화를 택했다. 그래서 옮기기 어려운 맥락이 많아 예외가 맞는 상황, 사용자가 이어가기를 직접 지시한 상황(`user-requested`)에서 AI가 예외를 올바르게 쓰는지는 이번 평가로 확인하지 못했다. 서버의 예외 판정·기록·대기 건 재인정은 자동 테스트로 검증했다.
- Claude는 두 시나리오 모두, 규칙이 카드에 기록되지 않았으니 하위 AI가 공유 지식에 기록하도록 지시에 넣었다.
- Codex의 댓글 쓰기 도구 `requestId` 형식 오류는 2026-10-29 평가에서도 관찰된 습관이며 이번 개정과 무관하다.

## 판정

- BEH-16·17: 네 실행 모두 통과다.
- BEH-02: Codex는 두 버전 모두 부분으로 같다. Claude는 1차 1회만 보면 개정 후가 낮았으나(통과 → 부분), 반복 실행을 합친 5회씩은 개정 전 통과 2/5, 개정 후 통과 3/5다. 사고 강도별로도 개정 후가 낮은 경우는 없다.
- 반복 실행 결과 개정 후 판정이 개정 전보다 나빠진 시나리오는 없다. 체크리스트 실행 절차 5항의 병합 제한에 해당하지 않는다. 1차의 차이는 실행 편차로 판단한다.
