# 문서 보관함과 AI 재구성

## 목적과 승인

기획 갱신(`spec-update`)과 규모 정리(`compact`)를 같은 전환 절차로 처리한다. AI는 원본을 분석하고 전환안을 작성하며, 제품은 버전 고정·전수 카드 대응·미완료 조건·참조 검증과 안전한 저장 환경을 제공한다. AI를 자동으로 시작하거나 사용자 대신 의미 검토를 승인하지 않는다.

분석 승인과 적용 승인은 별개다. MCP 적용에는 실제 사용자 승인 발언과 확인 가능한 대화 출처가 필요하다. UI 적용은 미리보기 후 의미 보존 확인 체크와 최종 확인을 거친다. 백업이 있다는 이유로 승인되지 않은 문서나 기획 범위를 변경하지 않는다.

## 보관과 삭제의 차이

- 보관 문서는 활성 목록·그룹 업무 집계에서 제외한다. 문서 ID와 버전, 카드 본문·공유 지식·완료 상태, 댓글, 이미지, 변경 이력, 일일 백업은 보존한다.
- 기존 `/mindmap/{mapId}/{cardId}` 링크와 외부 Ref는 계속 읽을 수 있다. 내용·댓글·이미지·AI 시작 등 변경 요청은 거부한다.
- 보관을 위해 원래 업무를 `done`으로 바꾸지 않는다. 복원은 원문을 활성화하며 후속 문서는 유지한다. 전환 전체를 되돌리는 기능과 개별 복원은 다르다.
- 휴지통으로 자동 이동하거나 영구 삭제하지 않는다. 이후 사용자가 별도로 복원·삭제하면 그 작업의 기존 정책을 따른다.

UI 진입: 좌측 목록의 **그룹 또는 문서 우클릭 → 문서 정리**. 그룹은 하위 문서를, 문서는 해당 문서만 대상으로 연다. 총괄 문서는 유지 대상으로 표시하고 선택에서 제외한다. 좌측 **보관함 · 문서 재구성**에서도 같은 화면을 연다. 활성 문서 우클릭의 **보관함으로 이동**은 개별 보관 기능이다.

정리 화면에서 규모 정리/새 기획 반영, 대상(최대 30문서), 현재 기준과 요청사항을 확인한다. 새 기획 반영은 AI가 조회할 원본 링크 또는 파일 경로·버전이 필수다. **AI 정리안 요청**은 분석과 해당 제안함 제출만 요청한다. 이어지는 기존 AI 옵션 화면에서 AI·모델·머신·작업공간을 선택하고 **AionUi에서 시작**을 눌러야 AI가 실행된다. 취소했다면 제안함 요청에서 AI 선택·시작을 다시 열 수 있다. 추가 AI 위임이나 문서 적용은 승인하지 않는다.

AI 결과는 별도 제안함으로 수신한다. 사용자가 JSON을 옮길 필요 없이 미리보기에서 원본 카드별 승계·통합·현재 지식·과거 근거·기획 제외의 이유와 새 문서/카드를 읽고 적용 여부를 판단한다. 직접 JSON 입력은 고급 메뉴로 유지한다. 요청과 제안은 `_document-reconstruction-requests.json`에 저장하며 원본 문서·댓글·업무 상태와 분리한다. AI 대화도 요청에만 연결하여 원본 카드의 대화 이력과 문서 버전을 바꾸지 않는다.

제안함에 제출된 정리안은 창 닫기·새로고침·서버 재시작 후에도 남는다. **문서 정리 → 요청과 AI 제안함 → 기존 요청 선택 → 미리보기 검증**으로 이어서 검토한다. AI 대화에만 있고 제안함에 미제출된 응답은 이 목록에 나타나지 않는다. 제출 전 사용자 입력, 직접 편집 중인 JSON, 승인 체크는 임시 상태이며 보존하지 않는다. 저장된 안과 현재 원본이 달라졌으면 적용을 막고 정리안을 다시 검토한다.

업데이트한 API와 MCP 프로세스를 다시 시작해야 신규 경로와 도구가 등록된다. UI만 갱신된 상태에서는 기존 활성 문서 목록은 유지하지만 보관·전환 기능은 사용할 수 없다. 실행 중 AI가 있는 운영 서버를 시험을 위해 임의로 재시작하지 않는다.

## AI 절차

우클릭 요청으로 시작한 AI는 `mindnprogress_get_reconstruction_request({requestId})`를 먼저 읽고 요청 범위를 확인한다. 아래 1~5단계로 정리안을 만든 뒤 `mindnprogress_submit_reconstruction_proposal({requestId,baseRevision,plan})`로 제안함에만 제출한다. `baseRevision`은 조회한 요청의 revision이며, plan에 approval을 넣으면 거부한다. 요청의 목적·기준·새 기획 출처·대상이 다른 안, 누락이나 오래된 원본을 가진 안도 거부한다. UI로 요청한 분석 작업에서는 6단계를 수행하지 않고 사용자의 별도 화면 승인을 기다린다.

1. `mindnprogress_get_reconstruction_context({mapIds})`로 지침, `sources`, `groupBaselines`, 전수 카드 목록을 읽는다. 일반 `get_context`의 대화당 1회 성공 규칙은 그대로 유지한다.
2. 원본 문서·카드·댓글·이미지와 그룹 기준을 읽는다. context 목록만으로 의미를 판단하지 않는다. 새 기획이 있으면 원본과 현재 구현의 차이를 별도 조사한다.
3. 모든 원본 카드를 `carry`, `merge`, `knowledge`, `history`, `drop` 중 하나로 분류한다. 원본은 어떤 분류에서도 삭제하지 않는다. `drop`은 새 기획에서 제외된 근거가 있을 때만 가능하다.
4. 새 문서를 현재 기준·계속할 업무·대기·현재 지식 중심으로 구성한다. 완료 이력은 원본에 남기고 유효 결론만 승계한다. 새 업무의 진행률과 전체 제품 요구사항 충족률을 구분한다.
5. `mindnprogress_preview_reconstruction({plan})`으로 구조·조건 보존을 검증한다. 사용자가 MnP 실제 마인드맵 미리보기를 열면 렌더 측정과 최종 배치 검증이 수행된다. MCP만으로 미검증 안을 적용할 수 없으며 AI가 렌더 측정값을 추측해 제출해서도 안 된다. 미리보기는 문서를 저장하지 않는다.
6. 카드 대응표와 의미 보존을 설명하고 적용 승인을 받는다. UI에서 적용하거나, 실제 렌더 검증 후 preview를 다시 조회해 `layoutPhase:'verified'`와 최신 `previewHash`를 확인하고 `plan.approval`에 실제 승인 발언과 출처를 기입하여 `mindnprogress_apply_reconstruction({plan,previewHash})`을 호출한다. 원본·참조 변경, 30분 검증 캐시 만료·퇴출 또는 서버 재시작 후에는 실제 미리보기부터 다시 검증한다.
7. 원본 보관·후속 문서·그룹 소속·미완료 조건·지식·참조와 전환 이력을 재조회한다. 후속 작업이나 실제 그룹 시험은 해당 단계의 별도 승인 범위를 따른다.

정리 기준의 실행 원본은 `src/utils/documentReconstructionGuide.mjs`다. MCP context와 UI가 같은 지침을 사용한다.

## plan 형식

```js
const plan = {
  id: 'manager-v04-compact-01', // 재시도에는 같은 ID와 같은 내용
  mode: 'compact',
  baseline: 'v0.4',
  reason: '현재 기준을 유지하며 완료 이력과 중복 업무 정리',
  sources: context.sources, // 문서 버전·본문 해시·댓글 해시·보관 상태 버전
  groupBaselines: context.groupBaselines, // 그룹 설정·소속의 정확한 스냅샷
  targets: [{ key: 'voice', title: '보이스 · 현재 작업', nodes: [], edges: [] }],
  decisions: [{
    mapId: '원본 mapId', cardId: '원본 cardId', disposition: 'carry',
    reason: '현재 기획에서도 계속 수행해야 하는 업무',
    targets: [{ key: 'voice', cardId: '새 cardId' }],
  }],
  // spec-update일 때 필수: newSource, changeSummary
  // drop일 때 해당 decision에 필수: evidence
  // 적용할 때만 필수: approval: { statement: 실제승인발언, source: 확인가능한출처 }
}
```

위 예시의 빈 nodes/edges와 예시 ID는 구조 설명용이며 유효한 전환안이 아니다. targets에는 완전한 nodes/edges를 넣는다. 각 카드는 고유한 `id`, `type:'mind'`, `data:{label,description,kind,isWork,status,progress}`가 필요하다. position은 생략할 수 있고 제공해도 배치에 사용하지 않는다. 계층은 집계 전용 root 하나에서 이어지는 트리이며 nodes 배열 안의 순서가 형제 순서다. 업무 체크리스트 결과와 진행률은 일치해야 한다.

## 배치 계약

`src/utils/mindMapLayout.mjs`의 `subtree-bounds-v1`을 서버·클라이언트가 공유한다. 왼쪽에서 오른쪽으로 깊이를 배치하고 하위 트리 전체 높이를 예약한 뒤 부모를 해당 영역 중앙에 둔다. 같은 계층의 최대 카드 너비로 열 간격을 계산한다. 실제 카드 본체와 대기 배지·접기 버튼·그림자 여유를 포함한 점유 영역 사이 최소 32px, 형제 트리 사이 48px, 열 사이 96px를 확보한다. 카드는 전체 펼침 상태로 검사하고 AI가 넣은 hidden·parentId·style 등 배치 우회 필드는 승계하지 않는다.

검증은 **초안 배치 → 실제 MindNode/외부 링크 카드 렌더 크기 측정 → 실제 크기로 재배치 → 최종 렌더 좌표·점유 영역 검사 → 사용자 승인** 순서다. Ref는 원본 데이터를 투영하여 표시 크기를 검사하지만 새 Ref 데이터에 과거 AI 대화 등을 복사하지 않는다. 폰트가 준비되지 않았거나 카드 측정 누락·겹침·검증 영역 이탈이 있으면 적용을 차단한다. 소수점 렌더 오차는 최대 2px만 허용한다.

`previewHash`는 정확한 전환안·참조 표시 데이터·배치 영역에 결합된다. 적용은 그 배치의 좌표로 저장하고 저장 결과도 비교한다. 실제 렌더 증명은 최대 20개/30분의 서버 메모리 캐시이며 영구 승인으로 취급하지 않는다. 화면 재진입은 측정과 승인부터 다시 수행한다. 기존 문서의 수동 좌표는 변경하지 않으며 이 보완은 재구성 후속 문서만 대상으로 한다. 이후 카드 내용·크기를 편집할 때 자동으로 재배치하는 기능은 포함하지 않는다.

미완료 업무는 실제 미완료 후속 업무가 필요하며 기존 체크리스트의 text/done을 모두 보존한다. 대기 label/note/resumeCondition은 후속 waitingItems 안에 보존한다. 미완료 blockedBy 관계도 새 ID로 연결한다. 같은 조건을 합칠 때는 원래 조건의 합집합을 유지한다. Ref는 새 실행 업무로 사용할 수 없다. 이미지 카드는 원본에 보관하고 새 문서에서 원본 링크를 사용한다. 과거 AI 대화를 새 카드에 복제하지 않는다.

서버는 새 카드의 `reconstructionSources`를 처리표에서 생성한다. 임의로 이 필드를 작성하지 않는다. 이력의 `decisions`는 승계 대상이 없는 history/drop까지 추적한다.

기존 카드 Ref는 `data.reference:{mapId,nodeId}`를 사용한다. 함께 생성할 새 문서의 카드를 참조할 때는 전환안에서 `data.reference:{targetKey,nodeId}`를 사용하면 서버가 새 문서 ID로 치환한다. Ref가 다른 Ref를 가리키거나 자기 자신을 참조하는 안은 거부한다.

## 저장·충돌·복원

문서 원문과 분리된 `_document-lifecycle.json`의 원자적 파일 교체가 활성 문서 전환점이다. 준비 상태에서는 새 문서를 활성 목록에 노출하지 않는다. 저장 도중 실패하거나 서버가 재시작되면 원본을 활성 상태로 유지하고 미완성 후속 문서를 보관한다. 같은 ID·같은 적용안을 다시 호출하면 기존 성공 결과를 반환한다.

문서 변경 요청은 평소 병렬로 처리하고, 보관·전환·되돌리기만 진행 중인 변경을 기다린 뒤 독점한다. 원본 본문/버전·댓글·보관 상태·그룹 기준을 검사한다. 실행 중·확인 대기·상태 불명 AI 또는 미종료 위임이 있으면 거부한다. UI의 오래된 편집기와 과거 AI 대화도 서버 쓰기 방어를 우회할 수 없다.

`mindnprogress_get_reconstructions({id})`로 상태와 대응표를 조회한다. 사용자 승인 후 `mindnprogress_rollback_reconstruction({id})`으로 되돌릴 수 있다. 후속 문서의 버전·본문·댓글이나 원본의 보관 상태가 달라졌으면 자동 되돌리기를 거부한다. 원본을 개별 복원하는 경우 후속 문서는 그대로 남으므로 중복 활성 여부를 별도로 판단한다.

## 현재 제한과 평가 기준

- 한 전환은 원본/후속 각각 최대 30문서, 후속 문서당 최대 2000카드다. 같은 그룹의 문서끼리 또는 그룹 밖 문서끼리 처리한다.
- 그룹 총괄 문서는 기준점으로 유지한다. 총괄 교체·기획 기준 수정·위임 상태 정리는 자동 수행하지 않는다.
- AI 선택과 시작은 사용자가 직접 확인한다. 제안함 도착 여부는 선택한 요청을 열어 둔 동안 갱신하며, AionUi의 응답·추가 질문은 해당 대화에서 확인한다. 실제 AI 실행과 실제 그룹 시험은 별도 사용자 승인 대상이다.
- 구조·문자열 검증은 요구사항과 지식의 의미 보존을 증명하지 않는다. 현재 결론의 누락, 상충, 잘못된 업무 통합, 새 기획의 누락은 사람이 별도로 검토해야 한다.
- 다음 정리는 현재 활성 후속 문서를 원본으로 삼는다. 보관 체인을 따라 이전 원문을 추적할 수 있다.
- 카드 감소율은 보조 지표다. 성공 조건은 현재 기준의 명료성, 미완료 조건·대기·현재 지식 보존, 참조 추적 가능성, 충돌 시 안전 중단과 복원 가능성이다.

우클릭 경로는 그룹/문서 대상 분리, 기획 원본 필수 입력, AI 옵션 연결과 실행 전 취소, 가짜 제안 자동 수신, JSON 없는 대응표 검토, 별도 적용 승인, 원본 불변을 브라우저에서 검증한다. 실제 AI는 실행하지 않는다. 서버·MCP는 제안함 재시작 보존, revision 충돌, 목적/기준/대상 고정, 열람자 쓰기 거부와 원본 대화 연결 불변을 검사한다.

배치는 가변 크기·돌출 영역·불균형/깊은 계층·형제 순서·동일 좌표 무시·측정 누락/변조 차단을 단위 시험하고, 실제 브라우저에서 카드 렌더와 미리보기 검증, 창 닫기/새로고침 후 저장된 제안 재개와 승인 초기화를 검사한다. API/MCP의 단위 시험용 측정 fixture는 실제 사용 경로가 아니며 브라우저는 DOM에서 측정한다.

브라우저 검증은 먼저 빌드한 뒤 `MNP_BROWSER_TEST=1`을 지정해 API 시험을 실행한다. 별도 headless Edge 프로필과 임시 서버만 사용한다. `MNP_BROWSER_BIN`으로 브라우저 실행 파일을 지정할 수 있다. 보관 링크·읽기 전용·목록·전환 이력·후속 출처·모바일 폭을 확인하고 임시 폴더에 검토용 스크린샷을 남긴다.
