# 문서 전체 검색

사람용 `전체 검색` 화면과 AI용 `mindnprogress_search_content`는 인증된 `GET /api/search`를 함께 사용합니다. 따라서 검색 범위, Ref 처리, 필터, 커서와 권한 경계가 두 사용 경로에서 달라지지 않습니다.

## 검색 범위

- 현재 호출 주체가 열람할 수 있는 활성 문서만 검색합니다. 보관·휴지통 문서는 제외합니다.
- 문서 제목, 카드 제목, 설명, 공유 지식, 댓글·답글, 체크리스트, 대기 항목과 사용자에게 보이는 업무 메타데이터를 검색합니다.
- Ref 카드는 배치 문서와 카드 위치를 결과에 유지하되, 제목·본문·댓글·업무 필드는 저장된 복사본이 아니라 현재 원본 카드에서 읽습니다.
- 내부 AI 대화 ID, 위임 ID 같은 운영 식별자는 검색 대상에 넣지 않습니다.

## 두 가지 모드

`ranked`는 검색어와 일치하는 필드별 결과를 관련도순으로 반환합니다. 일치 필드와 문맥 일부가 함께 오므로 빠르게 후보를 좁힐 때 사용합니다. 선택 범위의 문자열 일치는 전부 검사하지만, 다른 표현으로 작성된 의미상 관련 카드는 보장하지 않습니다.

`catalog`는 검색어 없이도 선택 범위의 모든 카드를 안정적인 순서로 반환합니다. 상위 검색 결과에 진짜 담당 카드가 없거나 전수 확인이 필요한 경우 `page.hasMore`가 `false`가 될 때까지 커서를 이어 사용합니다. 카탈로그도 간결한 후보 목록이므로 실제 담당 범위·상태·완료 여부를 확정하기 전에는 개별 카드의 최신 원문을 조회합니다.

## 필터와 페이지

문서·문서 그룹, 콘텐츠 필드, 카드 종류, 업무 여부, 상태, 담당자와 대기 항목 유무를 조합할 수 있습니다. 응답의 `page.total`, `page.hasMore`, `page.nextCursor`로 남은 결과를 확인합니다. 검색 조건이나 페이지 사이의 결과 집합이 바뀐 뒤 이전 커서를 재사용하면 서버가 잘못된 커서로 거부하므로, 첫 페이지부터 다시 조회해 조용한 누락을 막습니다.

예시는 다음과 같습니다.

```text
GET /api/search?q=전체+검색&mode=ranked&field=description&limit=25
GET /api/search?mode=catalog&groupId=group-id&limit=100&cursor=...
```

## MCP 응답 크기

`mindnprogress_search_content` 응답이 약 4만 자를 넘으면 MCP가 결과 내용은 줄이지 않고 한 번에 돌려주는 결과 수만 줄입니다(`mcp/searchBudget.mjs`). 서버 커서는 결과 집합의 지문과 다음 위치를 담으므로, MCP가 결과를 잘라 원래 커서를 넘기면 잘라낸 결과를 건너뜁니다. 그래서 앞쪽 결과 중 예산에 드는 개수를 정한 뒤 같은 조건·커서로 `limit`만 줄여 서버에 다시 요청하고, 서버가 만든 `page.nextCursor`를 그대로 돌려줍니다. 응답 맨 앞의 `responseBudget`에는 요청한 개수(`requestedLimit`), 돌려준 개수(`returnedLimit`), 다음 페이지로 미룬 개수(`deferredResults`)와 최종 글자 수(`returnedChars`)를 적습니다. 재요청 사이에 데이터가 바뀌어 결과가 커지면 다시 개수를 정하고, 커서가 맞지 않으면 서버가 기존처럼 거부합니다. 화면의 전체 검색에는 적용하지 않습니다.

검색 사용을 권하는 안내는 `read_me_first`·`get_context` 등에 넣지 않습니다. 필요하지 않은 호출이 늘어나는 것을 막기 위한 결정이며, 안내는 도구 설명과 검색 응답의 `guide`에만 둡니다.

서버와 MCP를 업데이트한 뒤에는 서버 재시작과 MCP 재연결이 필요합니다. 기존 문서와 카드는 자동으로 수정하지 않습니다.
