# Windows MnP 시작·종료·재시작

## 운영 기준

- 등록된 `\MindNProgress` 작업과 NHN 실행 계정·자동 실행 조건을 유지한다. 콘솔 노출 보완 시 승인된 실행 동작만 GUI 호스트로 전환하며 계정·트리거·재시도·실행 시간 제한은 바꾸지 않는다.
- 상위 `MindNProgress_Start.vbs`와 `MindNProgress_Start.bat`는 **재시작 후 브라우저 열기**, `MindNProgress_Stop.bat`는 **종료만** 수행한다. 모두 `scripts/mnp-runtime.ps1`을 호출한다.
- 사용자가 진행 과정을 보고 실행하려면 상위 `MindNProgress_Start.bat`를 연다. VBS와 동일한 재시작·호환 옵션·완료 대기·브라우저 열기를 사용하되, 공통 제어 스크립트의 진행 로그와 오류를 콘솔에 표시한다. 성공하면 창을 닫고, 실패했을 때만 입력 가능한 콘솔에서 키 입력을 기다리며 원래 종료 코드를 보존한다. 기존 VBS와 상시 실행 서버의 숨김 동작은 바꾸지 않는다.
- 시작 호출 설정은 `MindNProgress_Start.bat` 한 곳에서 관리한다. BAT는 인수가 없으면 콘솔 모드, `--hidden` 옵션이면 숨김·키 입력 대기 생략 모드로 같은 제어 명령을 실행한다. VBS는 BAT를 `--hidden` 옵션으로 숨겨 실행하고 완료 대기·실패 대화상자 표시만 담당한다. 두 파일의 주석에 수정 책임과 원본 동기화 규칙을 명시했으며, 옵션·종료 코드 계약 변경 시에는 양쪽을 함께 확인한다.
- 시작 아이콘의 재시작은 콘솔을 표시하지 않고 진행한다. VBS 실행 창 스타일과 PowerShell 창 스타일을 모두 숨김으로 지정하며, 완료를 기다린 뒤 브라우저를 연다. 실패 안내 메시지와 시간·오류 로그는 유지한다. 터미널에서 직접 실행하는 공통 명령의 출력은 그대로 유지한다.
- 예약 작업의 `MindNProgress_Launcher.cjs`는 장기 실행 런처다. AI 터미널에서 직접 런처나 개발 서버를 띄우지 않는다.
- 예약 작업은 `wscript.exe //B //NoLogo "<프로젝트>\scripts\runtime\task-host.vbs" "<확인된 node.exe>" "<설치 루트>\MindNProgress_Launcher.cjs"`를 실행한다. GUI 호스트가 Node 생성 시점에 숨김 스타일을 전달하고, 런처 종료까지 기다려 종료 코드를 예약 작업으로 반환한다. 바로 종료하는 분리 실행기가 아니다.
- 구형 예약 작업의 `powershell.exe -WindowStyle Hidden`은 PowerShell 초기화 전의 순간적인 콘솔 노출을 막지 못한다. 제어 명령은 검증된 구형·신형 동작만 허용하며 전환 전 기존 서버 종료와 전환 후 프로세스 계층 검증을 모두 유지한다.
- Git 밖의 상위 실행 파일은 `scripts/runtime/entrypoints/`에 재배포용 원본을 관리한다. 이번 교체 전 원본은 `../.mindnprogress/runtime-entrypoints-backup-20260914/`에 보관했다.

## 공통 명령

프로젝트 폴더에서 실행한다. `status`는 서버와 예약 작업을 변경하지 않는다.

AI와 사용자의 시작 아이콘 모두 아래 공통 제어 스크립트를 사용한다. `Stop-ScheduledTask`만 실행한 뒤 `Ready`를 중지 완료로 취급하거나, 별도 PID 강제 종료 명령을 즉석에서 만들어 재시작 절차를 대체하지 않는다. 작업 실행기와 자식 PID의 수명은 같지 않다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/mnp-runtime.ps1 -Action status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/mnp-runtime.ps1 -Action start
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/mnp-runtime.ps1 -Action stop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/mnp-runtime.ps1 -Action restart
```

검증된 GUI 호스트로 **승인된 일회성 전환**은 `-Action restart -UseGuiTaskHost`로 수행한다. 같은 제어 잠금 안에서 기존 서버 종료·포트 해제를 확인한 뒤, 기존 작업 XML을 `.mindnprogress/task-before-gui-host-*.xml`에 백업하고 실행 동작만 갱신한다. 실행 동작 외 XML이 그대로인지 검사한 후 같은 작업을 시작한다. 일반 재시작·시작 아이콘은 예약 작업 설정을 자동 변경하지 않는다.

최초 전환 시 실행 중인 구형 서버에는 정상 종료 IPC가 없다. 저장·편집을 마친 다음 한 번만 `-AllowLegacyStop`을 추가한다. 사용자가 실행하는 기존 시작/종료 아이콘에는 이 호환 옵션이 포함되어 있다. 신형 감시자가 확인되면 이 옵션이 있어도 정상 종료를 먼저 사용한다.

정상 종료 대기는 `-StopTimeoutSeconds` 기본 60초, 시작 대기는 `-StartTimeoutSeconds` 기본 120초다. `restart`는 정상 종료 제한을 넘기면 최초에 검증한 MnP 프로세스의 신원·NHN 계정·포트 소유권을 다시 확인한 뒤 남은 대상만 강제 종료한다. 강제 종료와 종료 확인에는 `-ForceStopTimeoutSeconds` 기본 10초의 별도 예산을 사용한다. 정상 종료 요청이 무응답이어도 최초 종료 예산을 새로 시작하지 않는다. 대상 식별 실패·다른 포트 소유자·제어 인스턴스의 명시적인 거부는 강제 종료 사유가 아니며, 기존 프로세스 종료와 포트 해제를 확인하지 못하면 새 서버를 시작하지 않는다. 시작 실패 후 kill·시작을 반복하지 않는다. `stop`은 기존과 같이 정상 종료 시간 초과를 오류로 반환하며 자동 강제 종료하지 않는다.

강제 종료는 진행 중인 저장을 중단할 수 있는 마지막 복구 수단이다. 정상 종료는 먼저 머신 오퍼레이션·Runner 롱폴·미완료 요청 본문·로컬 AionUi 호출과 확인 재시도 대기를 해제한다. 원격 실행이 이미 전달됐다면 결과 미확인으로 구분하고 종료 오류로 귀속 토큰이나 lease를 삭제·반납·격리하지 않는다. 종료 후 원격 실행 자체가 멈췄다고 간주하거나 자동 재전송하지 않는다. 종료 경로에 새 복구용 저장·원격 조회 대기를 추가하지 않는다.

API 드레인이 30초를 넘으면 남은 작업 이름과 경과 시간을 기록한다(`MNP_SHUTDOWN_DIAGNOSTIC_MS`로 조정). 진단 타이머는 추적 대상이 아니며 저장 대기를 포기하지 않는다. 기존 작업 드레인 이후 남은 연결의 유예는 기본 5초(`MNP_SHUTDOWN_CONNECTION_GRACE_MS`)이고, Runner 롱폴 기본 25초는 유지한다.

## 순서와 안전 장치

1. 실행 파일·설치 경로·예약 작업 인수·NHN 계정·프로세스 명령줄/생성 시각/부모 관계·포트 소유자를 확인한다. 테스트와 다른 세션의 동일 소스 서버는 배포 런처의 자손이 아니면 제외한다. 운영 포트를 다른 서버가 사용하면 중단한다.
2. 재시작 명령의 독점 파일 잠금을 유지한다. 예약 작업부터 중지하고, 남은 감시자에 설치 경로별 파이프와 실행 인스턴스 식별자로 정상 종료를 요청한다. 외부 HTTP 종료 API는 만들지 않는다.
3. API는 신규 요청과 반복 작업을 중지하고 종료 신호로 네트워크 대기를 해제한다. 처리 중인 요청 함수·명시적 백그라운드 작업을 기다리며 응답만 먼저 반환한 저장도 기다리고 SSE 연결을 정리한다. 이후 웹 서버를 닫고 실제 프로세스 종료를 확인한다. 내부의 초기화·드레인·웹 종료가 멈춰도 외부 컨트롤러의 정상 종료 제한은 유지한다.
4. 반복 확인에는 프로세스 핸들·기동 시각·실행 파일과 빠른 TCP 목록을 사용한다. PID 파일만으로 종료하지 않는다. 재시작의 최종 강제 종료는 처음 검증한 프로세스의 명령줄·생성 시각·부모 관계·계정을 다시 확인하고 핸들을 확보한 뒤 API·웹·감시자·런처 순서로 수행한다. 다른 프로세스나 새로 생긴 트리는 추가하지 않는다.
5. 기존 프로세스와 포트가 모두 사라진 뒤 같은 예약 작업을 시작한다. 웹/API HTTP 200과 API 상태, 새 PID/기동 시각, 실제 NHN 계정과 포트 소유자를 다시 확인한다. 기동과 최종 HTTP 검증은 `StartTimeoutSeconds`(기본 120초)의 **동일한 마감 시각**을 사용한다. 요청마다 900ms에 취소하거나 최종 확인에 별도의 5초 제한을 덧씌우지 않는다. 실패 시 예약 작업을 다시 시작하지 않는다.

사전·최종 포트 소유권 검사는 콘솔을 만들지 않는 `netstat -ano` 조회로 통일한다. TCP 수신 항목만 추려 IPv4·IPv6와 PID를 확인한다. `-p tcp`는 IPv6를 누락하므로 사용하지 않는다. NetTCPIP 공급자가 실제 수신 포트를 빈 결과로 반환해 시작 전 검사가 실패하는 경우에 의존하지 않으며, 조회 실패·빈 출력·해석할 수 없는 TCP 행은 포트가 비었다고 간주하지 않는다. 정상 조회에서 대상 수신 포트가 없는 경우만 빈 목록으로 처리한다. 기존 NHN 소유권·명령줄·생성 시각·부모 관계 검증은 그대로 유지한다.

HTTP 준비 검사는 전체 마감 안에서 **개별 시도를 최대 5초**로 제한하고, 멈춘 요청 이후에도 새 연결로 다시 확인한다. 이는 최종 검증 전체를 5초로 제한하거나 시작 제한을 늘리는 것이 아니다. 900ms보다 느린 정상 응답도 허용하며, 서버나 예약 작업을 다시 시작하지 않는다. 대기 중 `[http-wait]`에 웹/API 상태와 조회 시간을 표시하고, 한쪽만 실패해도 다른 쪽의 완료된 상태 코드를 로그에 보존한다.

`npm run dev`의 `--watch` 개발 경로는 유지한다. 예약 작업은 자동 코드 감시 재시작이 없는 stable 경로다. 개발 경로는 운영 제어 명령의 종료 대상에 포함하지 않는다.

- 실제 API에 미전달 머신 요청, 전달 후 결과가 없는 요청, 25초 Runner 롱폴, 본문이 멈춘 로컬 AionUi 응답을 함께 남긴 뒤 IPC 종료했다. 모두 `503 / RUNTIME_STOPPING`으로 해제됐고 API는 종료 코드 0으로 끝났다. 반복 측정은 약 0.1~1.7초였으며 1초 미만을 운영 보장으로 간주하지 않는다.
