# 임시 API 계측

지식 정리 한 건을 실행하는 동안 사용한 API와 비용을 비교한다. 계측 변경은 별도 커밋으로 보관하고 측정·분석을 마친 뒤 그 커밋을 `git revert`한다. 계측 파일은 업무 데이터와 분리된 `server/data/_api-diagnostics`에 보존된다. `MNP_DATA_DIR`을 지정한 환경에서는 그 데이터 디렉터리를 사용한다.

## 반영과 측정

서버 코드이므로 실행 중인 서버에는 재시작 후 반영된다. MCP 도구와 클라이언트는 변경하지 않는다. 서버 실행·재시작은 `mnp-runtime` 스킬과 현재 승인 범위를 따른다.

지식 정리를 시작하기 직전 저장소 루트에서 실행한다.

```powershell
node scripts/api-diagnostics.mjs begin
```

이 명령은 최근 15초 안에 갱신된 진단 파일을 확인하고 기존 MCP 사용 통계와 시작 시각을 구간 파일에 저장한다. 출력된 구간 파일 경로를 보관한다. 같은 시간에는 지식 정리 작업만 진행한다.

AI의 처리가 모두 끝난 뒤 출력받은 구간 파일을 지정한다.

```powershell
node scripts/api-diagnostics.mjs end --run "구간 파일의 실제 절대 경로"
```

약 2.5초의 로그 저장 대기 후 API별 호출 수·평균·P95·최대 관측 시간·연결 종료·HTTP 오류·미종료 요청·JSON 응답 문자 수를 출력한다. 기존 MCP 통계의 호출·실패·응답 문자 수 차이도 출력한다. 상세 결과는 구간 파일 옆의 `.report.json`에 저장한다. 표의 `runner`는 Runner의 정기 통신, `mcp`는 대화 식별 헤더가 있는 요청, `other`는 그 밖의 요청이다. `other`에도 식별 헤더 없는 MCP와 화면의 자동 갱신이 포함될 수 있다.

지정 구간을 다시 집계하려면 다음처럼 실행한다. 처리 중이던 요청이 뒤늦게 끝난 결과도 재집계할 수 있다.

```powershell
node scripts/api-diagnostics.mjs report --from "시작 시각 ISO 8601" --to "종료 시각 ISO 8601" --json
```

## 기록과 해석

- 모든 일반 API의 시작, 응답 완료 또는 연결 종료, 서버 처리 종료를 각각 기록한다. SSE 연결은 제외한다. 연결 종료 뒤에도 서버 작업은 원래 동작대로 계속될 수 있으며 그 최종 처리 시점을 별도로 기록한다.
- 기존 문서 잠금 대기·문서 읽기·Ref 처리·그룹 조회 구간과 JSON 변환 시간을 기록한다. 대기 도중 연결이 끊어져도 진행 중인 단계와 경과 시간을 남긴다. 잠금 알고리즘·보유자 추적·자동 취소·재시도 정책은 바꾸지 않는다.
- 서버 전체의 CPU 사용량, 메모리, 이벤트 루프 지연, 처리 중 요청 수와 오래 처리 중인 요청 일부를 5초 간격으로 기록한다. CPU는 프로세스 전체 값이며 API별 CPU 비용이 아니다. CPU 100%는 CPU 코어 하나를 계속 사용하는 양에 해당한다.
- 소요 시간 합계는 동시 요청의 시간을 합친 값이므로 작업의 실제 경과 시간과 다르다. 응답 문자 수는 생성한 JSON 길이로서 실제 전송 완료량과 다르다. `aborted`만으로 사용자의 취소와 타임아웃을 구분할 수 없다.
- MCP 사용 통계는 실행 머신의 파일을 읽는다. 다른 머신에서 실행한 MCP 통계는 해당 머신에서 별도로 확보해야 한다. API 로그는 이 서버에 도착한 요청을 대상으로 한다.
- 로그는 1초 간격으로 비동기 저장한다. 대기 버퍼는 1 MiB, 프로세스별 파일은 약 64 MiB로 제한한다. 제한 또는 저장 실패가 발생하면 불완전한 계측임을 표시한다. 프로세스가 강제 종료되면 마지막 미저장 구간이 누락될 수 있다. 이전 프로세스의 파일은 자동으로 삭제하지 않는다.
- 본문·댓글·인증 헤더·쿼리 문자열은 기록하지 않고 시작 확인 토큰은 가린다. API 경로에 포함된 문서·카드 ID는 진단 파일에 남는다.

## 원복

측정 결과를 확보한 뒤 임시 계측 커밋만 `git revert`하고 승인된 절차로 서버를 재시작한다. `server/data/_api-diagnostics`의 증거 파일은 Git 원복 대상이 아니므로 유지된다. 원복 후에는 집계 스크립트도 제거되므로 원복 전에 상세 보고서를 생성한다. 환경 설정이나 새 MCP 도구를 추가하지 않아 별도 설정 원복은 필요 없다.
